# Wall Dashboard (MagicMirror)

A **fixed, wall-mounted tablet** showing a kid-friendly info screen — weather, today's calendar,
and freely configurable widgets, including custom-coded ones. Built on **MagicMirror²**, whose
entire architecture is modular widgets, so adding, configuring, and writing your own is the normal
workflow — not a hack.

> **Prerequisites:** a working Proxmox host
> ([Installing & Hardening Proxmox](/en/01-proxmox-install-harden)), and an understanding of the
> [LXC-vs-VM decision](/en/01-proxmox-install-harden#two-guest-types--pick-well).

## Why MagicMirror

- **Everything is a module** placed into a **region** (`top_left`, `top_right`, `middle_center`,
  `lower_third`, `bottom_bar`, …). Hundreds of community `MMM-*` modules exist (weather, iCal,
  transit, photos, RSS). Composing the screen = listing modules in `config.js`.
- **Custom widgets are first-class** — a folder in `modules/` with a frontend JS (`getDom()`), an
  optional server-side `node_helper.js` (for API calls / secrets), and CSS.
- **Display-first, not an app framework.** Touch works, but stateful interaction (e.g. a todo
  list) is better delegated to a real app in an **iframe**.

## Platform decision

| Question                     | Answer               | Why                                                                         |
| ---------------------------- | -------------------- | --------------------------------------------------------------------------- |
| Needs Docker?                | **No**               | Plain Node app; community-scripts installs it directly.                     |
| Wants host bind-mount?       | **No**               | Calendar via network ICS, other apps via network iframe — no host ZFS data. |
| Hard isolation / own kernel? | **No**               | Internal, low-risk display app.                                             |
| **Result**                   | **unprivileged LXC** | Also a stronger default escape posture than a lone Docker container.        |

## Install (community-scripts LXC)

Find MagicMirror on [community-scripts.org](https://community-scripts.org/scripts/magicmirror) →
copy its `bash -c "$(curl -fsSL …)"` line → audit the script → run it **(host)**. It creates an
unprivileged LXC and installs Node + MagicMirror (under `/opt/magicmirror`).

## Deploy from this repo

Sync the repo to the host, then push modules + config into the LXC:

```bash
# (Mac) — sync everything to the host
scripts/deploy.sh root@192.168.1.10

# (host) — push wall-dashboard files into CT 101
/opt/homelab/projects/wall-dashboard/install.sh 101
```

Module code is overwritten every deploy. **Config is per-host and never overwritten** — the repo
ships sanitized placeholders, so `install.sh` pushes `config.js`/`custom.css` as `*.sample`. On the
first deploy, copy a sample into place, then edit the live copy (your real tokens/IPs stay only on
the host):

```bash
# (host) — one-time, per config file
pct exec 101 -- cp /opt/magicmirror/config/config.js.sample /opt/magicmirror/config/config.js
pct exec 101 -- cp /opt/magicmirror/config/custom.css.sample /opt/magicmirror/config/custom.css
```

## Editing the live config

`config.js` and `custom.css` are **per-host** — your real tokens/IPs/names live only inside the LXC
and a deploy never overwrites them. Edit them in place. The container's filesystem is mounted on the
Proxmox host via its ZFS subvol, so you can edit the real files straight over the host's SSH — no
sshd, keys, or `pct` dance inside the container:

```bash
# (Mac) — open the live config dir in your editor over SSH
zed ssh://pve/rpool/data/subvol-101-disk-0/opt/magicmirror/config
```

The subvol mountpoint is a persistent ZFS property, mounted on the host whether the container is
running or stopped, so this path is stable across reboots. For another CTID/storage, derive it with
`pct config <ctid>` + `zfs list`.

Applying a change depends on **which** file you touched:

| Changed      | How to apply                                         |
| ------------ | ---------------------------------------------------- |
| `config.js`  | Read at startup → **restart** the service            |
| `custom.css` | Client-side only → **reload the tablet**, no restart |

```bash
# config.js: validate first (a syntax error blanks the dashboard), then restart
ssh pve 'pct exec 101 -- node -e "require(\"/opt/magicmirror/config/config.js\"); console.log(\"config OK\")"'
ssh pve 'pct exec 101 -- systemctl restart magicmirror'
```

Then reload the tablet kiosk (pull-to-refresh, or re-open `http://<lxc-ip>:8080`).

## Config — regions + widgets

`/opt/magicmirror/config/config.js` inside the LXC. `serveronly` mode binds localhost by default —
open it up for the LAN so the tablet can connect. Replace `YOUR_TOKEN_1` / `YOUR_TOKEN_2` with
your real iCloud calendar tokens.

<CodeSnippet file="projects/wall-dashboard/config/config.js" />

> **Keep it one file — and keep callbacks self-contained.** Don't try to split `config.js` with
> `require("./other.js")`: MagicMirror loads the config by **compiling it from a string**
> (`require-from-string`), so relative requires have no directory to resolve against and the module
> crash-loops. For the same reason, an `items`/`badges` **callback is serialized to source and
> re-evaluated in the browser** — it can reference only its `ctx` argument and built-ins. Any helper
> it uses (a `pickDaily`, a lookup table) must be defined **inside the function body**, not at the
> top of `config.js`, or the widget throws `ReferenceError` client-side.

## iCloud calendar — read-only ICS

The `calendar` module needs a **public ICS URL** per calendar. Three cases:

- **Your own iCloud calendar** → publish it: **Mac Calendar** → right-click the calendar → **Share
  Calendar** → tick **Public Calendar** → copy the link (a published iCloud calendar URL).
  Read-only, auto-refreshing, no auth.
- **A calendar you subscribed to** → you already have the source URL: **Mac Calendar** → select
  it → **Edit** (or File → Get Info) shows the subscription URL.
- **A calendar shared with you via iCloud** (not subscribed) → it has no public ICS unless the
  owner publishes one — ask them to do the "Public Calendar" step and send the link.

Notes:

- Use the **`https://`** form (the module doesn't handle the webcal scheme).
- **Per-calendar colors** — give each entry a `color` (+ optional Font-Awesome `symbol`) and set
  module-level `coloredText: true` / `coloredSymbol: true`.
- **Unpublish → republish** rotates a leaked calendar token.

## Theming

MagicMirror has **no theme engine** — theming is plain CSS cascade. `css/main.css` defines
everything via `:root` CSS variables; overrides go in **`config/custom.css`**, which loads last.
Activate it once: `cp config/custom.css.sample config/custom.css`.

Set `--theme` at the top of `custom.css`. Change one line, reload the tablet, done — no restart
needed (CSS is client-side; see [Editing the live config](#editing-the-live-config)).

## Custom widgets

A module is a folder in `modules/MMM-*/` with a frontend JS (`getDom()`), an optional server-side
`node_helper.js`, and CSS. That's the whole loop: `getDom` draws, `node_helper` fetches, socket
notifications carry data between them.

### MMM-Routine

Per-kid morning checklist at the bottom of the screen. Tap to check off; resets every midnight
(date-keyed `localStorage`). First to finish gets 🏆, beating the deadline earns ✨.
Purely client-side — no `node_helper`.

Each child's `items` is either a **fixed array** or a **callback** `(ctx) => items` that builds
today's list from context — day of week, time, today's calendar events, and the weather DayParts
already fetched (broadcast as a `DAYPARTS_WEATHER` notification). The `RoutineCtx` shape is a JSDoc
typedef at the top of the module, so editors autocomplete it with `// @ts-check` — no build step,
config stays plain JS. Done-state is keyed by item **label** (not index), so a callback can add or
drop items on re-render without scrambling the checkmarks — keep labels unique per child.

The reward emojis are configurable too, via a module-level `badges` key — an object (or `(ctx) =>
object`, same pattern as `items`) with `leader` / `done` / `beatDeadline`. Missing keys keep their
defaults (🏆 / ⭐ / ✨), so let the kids pick their own from
[emojis.wiki/success](https://emojis.wiki/success/):

```javascript
badges: { leader: "🥇", done: "😎", beatDeadline: "⚡" }
```

```javascript
{
  name: "Kind 1", color: "#2ecc71",
  // fixed list still works — or return one dynamically:
  items: (ctx) => {
    // this child's events: calendar color === child color (see the calendars config above)
    const mine = ctx.calendar.filter((e) => e.color === ctx.color);
    // today's event somewhere other than home/school — a plain free-text test, no coordinates
    const away = mine.some((e) => e.location && !/schule|kita|zuhause/i.test(e.location));
    return [
      { icon: "🛏️", label: "Umziehen" },
      { icon: "🥐", label: "Frühstück" },
      { icon: "🪥", label: "Zähne" },
      // Tuesday = Sport → pack the gym bag
      ...(ctx.dayOfWeek === 2 ? [{ icon: "🎽", label: "Sportzeug" }] : []),
      // cold morning → jacket
      ...((ctx.weather?.[0]?.temp ?? 20) < 8 ? [{ icon: "🧥", label: "Jacke" }] : []),
      // school trip on this child's calendar today (title or location)
      ...(mine.some((e) => /ausflug/i.test(e.title + " " + e.location)) ? [{ icon: "🎒", label: "Rucksack" }] : []),
      // out-of-house appointment today → pack a water bottle
      ...(away ? [{ icon: "🚰", label: "Trinkflasche" }] : []),
    ];
  },
}
```

## Embedding other apps (iframe)

**[MMM-iFrame](https://github.com/alberttwong/MMM-iFrame)** drops any URL in as a tile — a todo
app, a Grafana panel, Home Assistant. The embedded app must **allow being framed**: apps that send
`X-Frame-Options: DENY` or `frame-ancestors 'none'` refuse to load. Since these are your own
containers, you control it — configure the app to allow framing, or relax the header at a reverse
proxy.

```javascript
{
  module: "MMM-iFrame", position: "lower_third",
  config: { url: ["http://192.168.1.30:2021/"], width: "100%", height: "420" },
}
```

## Tablet kiosk

- **iPad:** open the URL in Safari → **Guided Access** to lock it fullscreen; Settings → Display →
  **Auto-Lock: Never**; keep on charger.
- **Android:** **Fully Kiosk Browser** (or Fullscreen Immersive) pointed at the URL; disable
  screen timeout.
- Point at the reverse-proxy HTTPS name once that's up, else `http://<lxc-ip>:8080`.
