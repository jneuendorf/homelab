# Building a Proxmox Homelab

A practical, opinionated build log turned into a guide: how to take one small mini-PC and turn it
into a resilient, self-hosting platform — with the reasoning behind each decision, not just the
commands. Everything here runs on a **single node**; nothing assumes a rack, a cluster, or a NAS.

The guiding principle throughout: **redundancy is not a backup, and a backup you haven't restored
from isn't a backup yet.** Each phase builds the safety net before the thing it protects.

## The mental model

Everything in the series serves one data-flow rule:

> **Fresh data lands on the host, then flows outward: host → on-site → off-site. Never inward.**

| Tier | Where | Protects against |
|---|---|---|
| **Source of truth** | Host NVMe mirror (ZFS, 2-disk) | one disk dying · "oops" edits (snapshots) |
| **Copy #2 — local** | on-site SSD (always plugged) | host / pool death |
| **Copy #3 — off-site** | off-site SSD (rotates out of the house) | fire · theft |

The host is redundant and self-healing, so that's where you organize data. The backups radiate
outward from it — you never tidy a backup, and fresh data never lands on a bare USB stick first.
